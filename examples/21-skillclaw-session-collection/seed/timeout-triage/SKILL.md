# 支付接口超时调查

先从告警确认服务名、region 和 environment。每次工具查询都应带上这三个字段，不混用其他环境的结果。

这是一次分支式初查，不是全面排查。先取得下面两项结果，再选择适用分支；报告之后的建议留给下一轮，不因还有工具可用就继续扩大调查。

1. 调用 `query_service_health` 和 `query_upstream_latency`，取得服务健康与上游延迟的回执。这两项检查互不依赖，可以并行。
2. 如果服务不健康，报告该现象，把部署信息核对列为后续建议。如果上游 p95 超过 1000 毫秒，报告上游延迟异常，把上游依赖调查列为后续建议。任一异常成立，就结束本轮，不进入“以上检查都正常”的分支；这些现象本身不能确定最终根因。
3. 只有服务健康且上游 p95 不超过 1000 毫秒，才进入正常分支。若请求仍然超时，说明当前方法尚未定位问题，报告已取得的回执和仍需补充的检查。用户若明确补充了适用于这一分支的方法，则执行补充方法后再报告。

没有实际调用工具的检查只能写成建议，不得当作已经验证的结论。
