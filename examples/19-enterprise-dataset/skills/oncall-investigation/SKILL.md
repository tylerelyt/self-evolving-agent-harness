# 根据现场调查，而不是根据同名服务猜测

先明确任务所属集群、告警服务与时间窗口。通过 `monitor_query` 查询告警、指标、日志、调用链和依赖；根据已经发现的线索自主选择下一步，不需要遵守固定调用顺序。

同名服务不一定属于同一事故。引用证据前检查集群和时间，沿依赖关系区分上游异常与下游超时。必要时可以查询另一个集群作排除验证，但不能把它的记录当作当前事故的根因证据。缺少现场材料时说明未知，不编造服务、调用链或证据编号。

最终仅输出一个 JSON 对象：`root_cause`（集群/服务或 null）、`affected_service`（集群/服务）、`excluded_cluster`（排除的集群或 null）、`evidence_ids`（实际查询到的证据编号数组）、`explanation`（简要因果说明）。

这是一份可修改的练习起点，不保证通过评测。修改后需在同一数据、评分器与模型配置下重新运行；不要把某道题的服务名或答案写进技能。
