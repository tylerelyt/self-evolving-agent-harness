# 第 11 讲：一句纠正，最后走到哪一步？

本练习对应本讲观察题：在一个小任务中补充已核实、以后仍有用的事实，不要求 Agent 记住；观察后台是否复盘、是否写入，再用同配置的新会话做同类任务，看它是否采用新事实。

一次任务查对、把事实写进记忆、新会话采用事实，是三个需要分别观察的结果。脚本不要求它们全部成功，也不替模型写记忆。

## 运行

先按仓库说明准备固定版本的 Hermes：`bash scripts/setup_deps.sh`。这里只使用现有依赖，不另装框架。

```bash
export GLM_API_KEY='你的智谱 API Key'
bash examples/11-background-review/run.sh
```

默认模型为 `glm-5.2`，地址为智谱官方 `https://open.bigmodel.cn/api/paas/v4`。可以用 `GLM_MODEL`、`GLM_BASE_URL`，或命令参数覆盖：

```bash
bash examples/11-background-review/run.sh --model glm-5.2 \
  --base-url https://open.bigmodel.cn/api/paas/v4 --review-timeout 300
```

只读取调用方提供的 `GLM_API_KEY`，不回退其他供应商密钥，也不读取个人 `.env`。若依赖源码目录存在 `.env`，入口会停止，避免上游隐式加载它。每次运行创建独立的 `runtime/run-时间-随机编号/hermes/`，不使用个人 `~/.hermes`，不复用上次练习的记忆。记录可能包含完整模型输入输出，分享前仍需检查。

主流程有三次前台调用，每次最多六次迭代；原生后台实例的上限由固定 Hermes 版本决定，目前为十六次。等待期限不是计费上限。练习不自动重试整次运行，不保证每次都触发复盘或留下记忆。

## 按题目观察

### 1. 先做一项实际查询

Agent 接到支付日志调查任务。告警携带迁移前采集的入口样本和明确时段，但没有规定查询顺序。它可使用 `lesson11_logs` 的两个只读动作：

- `describe`：返回已核实的部署与迁移记录。
- `read`：按入口和带时区的时间范围查询日志，返回实际筛选结果。

业务数据是本地构造的教学材料，不是生产请求；模型调用与工具执行是真实的。旧入口保留迁移前记录，当前入口有两个告警时段的日志。数据、迁移说明和回执使用同一份定义，可在 `scene.json` 中核对。工具没有文件写入、任意命令执行或修改业务数据的能力；原生 `memory` 工具仍对前台开放。

Agent 可能先用旧入口得到空日志，也可能先查部署，直接找到当前入口。两种路径都保留。没有发生误解时，就记录“自行查对，随后确认事实”，不把这次运行说成成功纠正了一个错误。

### 2. 补充正式说明，而不是要求记住

在同一个 Agent 的第二轮，输入已经核实的迁移说明，要求复核同一告警时段。不包含“请记住”或“请复盘”，不规定 memory 的操作及内容。

配置将原生 `memory.nudge_interval` 设为 2，便于在短练习中观察轮次条件；Skill 自动复盘关闭。脚本不赋值复盘计数，不直接调用后台派生函数，不覆盖原生复盘提示。是否触发由 Hermes 正常收尾判断决定；前台的 memory 调用等因素也可能影响这次观察，应查看实际计数与回执。

本练习还关闭工具搜索的延迟加载，让日志工具直接出现在模型工具列表中；新会话沿用同一设置。它改变的是工具呈现，不是查询顺序或复盘触发条件。

观察器只包装并调用原派生方法和原 worker，保存后台收到的会话、提示、工具请求、同编号回执和异常。它在原生派生之前记录前台结束时的文件，再与后台开始、结束时的文件分别对照。因此前台保存、后台保存和文件最终变化不会混为一个结果。

前台返回后，练习观察者才等待后台。默认最多等待 300 秒；`--review-timeout 0` 表示一直等。超时会记录 `pending_at_exit` 并停止后续任务，退出进程可能中止原生 daemon；不能把它算成复盘结束。重跑会创建新运行，不会续跑那个已退出的线程。

### 3. 新会话不再重复纠正

等待已有后台结束后，新建独立 `AIAgent`，使用相同模型、工具、配置与本次教学 Home，启动历史为空。它只收到另一个时段的同类告警，没有旧入口、迁移说明或“先用新入口”的提醒。

查看 `sessions/fresh.json` 中实际加载的记忆，再看新会话的工具顺序及完整回答。程序只标记是否查到了正确入口和本次指定时段的非空日志，同时记录第一次业务动作与旧入口尝试；它不会把“回答提到了入口”当成采用，也不会把现场重新发现入口说成记忆起了作用。

## 去哪里核对

每次运行结束会打印唯一入口 `runtime/<本次编号>/REPORT.md`。同目录保留：

| 文件 | 对应的观察 |
| --- | --- |
| `scene.json` | 正式说明与构造日志是否相符 |
| `turns/01-task.json`、`02-correction.json` | 两轮完整输入输出、前台工具回执、返回时点与原生计数 |
| `reviews/<轮次>.json` | 派生、启动、结束时点；后台输入、提示、新增调用与回执 |
| `sessions/original.json`、`fresh.json` | 不同 Session 编号、空启动历史、实际加载的记忆 |
| `turns/03-fresh.json` | 未重复纠正的新任务输入与实际查询 |
| `memory/*.diff` | 每轮开始到等待结束的文件差异；前后台归属另看对应快照 |
| `observation.json` | 三轮记录及行为观察的统一索引 |

未触发、复盘未写入、写入但新会话未采用，都返回正常观察结果，不要求读者重复运行直到“学会”。鉴权失败、模型请求异常或前台未正常完成属于执行问题，返回非零退出码，并保留已经取得的材料。`observed` 只表示主流程观察结束，不表示学习成功。

原来的两个触发对照保留为可选项，不占主线：

```bash
bash examples/11-background-review/run.sh --controls
```

它们在独立控制会话中关闭 Memory/Skill 检查，随后重新开启 Memory 检查并从另一线程请求中断。是否真的中断、有没有派生，都按原生返回记录；定时器发出中断请求不等于模型必然已被中断。

## 思考题：复盘启动了，文件为什么没有变化？

会话包含已核实、后续仍有价值的新事实，后台复盘已启动，但记忆文件没有变化。怎样区分已有等价记忆、模型漏记和执行失败？

先读后台实际收到的会话和提示，确认事实没有遗漏，再检查线程是否结束。线程结束后，比较已有记忆是否表达同样意思；没有等价记忆时，再检查是否发起写入、参数和回执是否成功、有没有异常。成功回执与文件变化也需要对应核对。

这些材料可以帮助判断，但脚本不自动给“模型漏记”或“已有等价记忆”贴标准答案。语义是否等价、事实是否值得长期保存，仍需读完整内容。没有文件变化本身不足以得出其中任何一种结论。

```bash
# 不导入模型 SDK，不需要凭据，不联网；只验证现场及观察器
python3 -B examples/11-background-review/test_offline.py

# 用已安装的 Hermes 检查初始化、配置与工具实际分派；禁止网络，不调用模型

# 删除你指定的本讲已停止运行；包含教学 Home 和全部观察记录，不可恢复
python3 -B examples/11-background-review/run_background_review.py --clean run-YYYYMMDD-HHMMSS-xxxxxxxx
```

把最后一个参数换成本次输出的完整运行编号。清理不接受任意路径，不处理其他讲次，也拒绝清理仍在运行的进程。默认结束时只关闭 Agent 资源，保留记录。原 `.hermes-home/` 和旧 `output/` 不会被新入口读取或自动删除。

本次修订的本地验证：八项离线检查通过，覆盖日志时段、回执配对、等待状态、独立新会话，以及“未写入、未采用也能正常结束观察”的完整驱动流程；现有 Hermes 的初始化、配置和工具分派检查通过。驱动流程使用测试替身，不证明模型会采用事实。修订后尚未进行真实模型演练，不能沿用旧偏好示例的成功记录。
