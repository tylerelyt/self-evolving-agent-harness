# 第 18 讲：告警诊断的业务评测

本讲比较同一 GLM 模型使用两版诊断技能时的业务表现：新技能能否处理多告警，又是否让原来的单告警诊断被其他集群的同名服务干扰。先校准评分器，再运行隔离的逐题对照，最后决定是否值得采用。

## 本讲独立练习

旧版、候选版、反例版和四道固定故障题都由本目录提供，无需先生成一份 Skill。先用已知轨迹校准评分器，再让每版在独立会话里处理相同快照，查看结果、证据归属和查询过程的差异。

交付 `scorer-selftest.json`、一组同题旧版与候选回执，以及 `result.json` 的逐题比较。挑一条跨集群错误，说明即使最终答案出现正确服务名，为什么仍然不能通过。改评分规则后，用新目录重评全部版本。

在仓库根目录先校准评分器。这一步使用 Python 标准库，无需模型凭据。

```bash
bash examples/18-business-eval/run.sh --offline
```

准备固定 Hermes 依赖后，再运行完整对照。三版技能、四道题各重复两次，共 24 个独立会话。

```bash
bash scripts/setup_deps.sh
bash examples/18-business-eval/run.sh
```

也可打开 [workshop.ipynb](workshop.ipynb) 分步运行。当前执行后端使用 **macOS `sandbox-exec`** 隔离评分材料；其他平台会明确停止，不降级裸跑。没有设置 `GLM_API_KEY` 时隐藏询问。默认请求智谱官方端点；允许通过 `GLM_BASE_URL` 显式连接兼容端点或本地预算代理，临时令牌使用 `GLM_API_KEY`。报告分别记录执行端点与上游确认状态，不把本地代理地址当成真实上游。

每次运行独立保存在 `runtime/alerts-*`，终端给出 `REPORT.md` 路径。先看逐题比较，再查 `rows.json` 中的真实调用、工具回执和评分原因。`Ctrl-C` 或 Notebook“中断内核”停止运行，并终止当前执行进程组；已完成记录保留，不启动常驻服务。密钥不落盘，运行输出和日志不发布。

## 课后练习

新加入的多告警联合诊断技能改善了多服务问题，却在旧单告警任务上把其他集群的同名服务串进来。怎样组织一次公平评测，区分根因与下游症状、核查集群和时间归属、检查工具过滤条件？怎样用已知对错样本校准评分器，并在评分方法改变后重评两版？采用时又怎样权衡新增收益、旧任务退步和成本？

本例的[题库](alert_dataset.py)是**构造教学数据**，并非生产事故。开发题与留出题明确区分，不根据留出题结果自动修改技能。

| 题号 | 场景 | 核查重点 |
| --- | --- | --- |
| A01 | `prod-eu` 单个 `checkout-api` 告警 | 找到 `db-gateway` 根因，而非只复述下游超时 |
| A02 | 同集群两个服务同时告警 | 找到共同上游并列出全部受影响服务 |
| A03 | 单告警混入 `staging-eu` 的同名记录 | 查询保留集群过滤，引用属于当前事故和时间窗口 |
| A04 | 只有告警，日志与链路缺失 | 保留未知，不猜根因 |

先阅读 [alert-skills/](alert-skills/) 中的原版、候选版和故意漏掉集群过滤的反例版。反例是给模型的方法，不是预先写好的模型输出；模型可能纠正它，因此不强制反例一定失败。

## 如何比较

[alert_protocol.json](alert_protocol.json) 固定 `glm-5.2`、温度、重复次数和预置记忆，所有版本统一最多16轮。每题每版使用相同输入与业务快照、新 Home、新 SessionDB，只暴露只读查询和技能读取工具。执行进程不能读取题库预期、评分器、其他技能版本或历史验证文件；可读的是本题输入、业务快照和本版技能。

回答中的 `root_cause` 是根因服务ID，不是故障描述；`affected_services` 只列目标集群和时间窗口内实际出现告警的服务ID，根因服务只有自身也出现告警才计入。工作目录已设置好，直接调用 `./incidentctl`，不需要 `cd`，也不允许 `&&` 等命令拼接。

[alert_scorer.py](alert_scorer.py) 分别检查业务字段、实际引用、请求与回执配对、过滤条件和格式。唯一 JSON 代码块可以提取，内容与纯 JSON 格式分列；块外解释、多个块或歧义保留人工复核，不自动通过。调用轮数耗尽或违反已公开命令约束记为任务失败；连接、工具执行或评分基础设施失败留空评分。改变协议或评分器后必须重评全部版本，输入、快照或评分版本不一致的结果不得比较。

学员应检查逐题改善与退步，尤其不能用平均分掩盖旧关键任务退步；再读因果说明，比较耗时、调用次数和工具数量。程序只给出继续验证或拒绝采用的提示，不自动提升版本，也不把解释是否充分、成本是否值得采用伪装成标准答案。当前仅完成离线核查，真实模型表现与预算仍待实际运行确认。
