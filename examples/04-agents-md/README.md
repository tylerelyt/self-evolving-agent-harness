# Lab 04｜旧任务中的纠正，怎样进入新任务？

[打开 notebook](workshop.ipynb)，使用 Python 3.12 内核从头运行。未设置 `GLM_API_KEY` 时，准备格会弹出隐藏输入框；全程只需输入这一个密钥。缺失的 `openai-codex==0.154.0`、`litellm[proxy]==1.101.0` 和 `httpx[socks]` 会自动补装。

这是专栏《自进化 Agent 实战》04 讲《AGENTS.md：如何设计规则指导 Agent 未来行动》的配套练习。练习使用构造的事故调查材料，目标是掌握处理真实场景的能力。

| 十二格导览 | 动手做什么 | 跑完看什么 |
| --- | --- | --- |
| cell0—2｜题面、参考答案与准备 | 阅读规则范围设计题，一键准备材料与连接 | 一次对话的纠正与长期项目要求的区别 |
| cell3—5｜上一次已经改对，为什么新的任务又错了？ | 在旧会话生成旧稿并纠正，再独立调查另一份材料 | “阶段/本次回答”，以及新任务输入中是否出现旧纠正 |
| cell6—8｜哪些纠正值得留下？ | 分出旧实例与参数，核对团队确认的三条通用要求 | 哪些留在旧任务，哪些进入项目要求 |
| cell9—11｜规则写在哪里，决定哪些任务会使用它 | 从根目录、服务目录分别启动，再临时替换服务规则 | 两级加载范围、实际回答、同层选择与撤下结果 |

第一阶段直接用 `codex.thread_start(cwd=str(payment), ...)` 创建旧会话，再用 `thread.turn()` 和 `turn.run()` 生成和纠正报告。旧初答明确按提示指定的“先发生即原因”写法生成，用于演示纠正过程，不作为模型自然犯错率的测量。新任务在独立会话中分析另一份材料；即使回答没有再犯错，也要检查实际输入，不能据此认定旧纠正自动留下了。

第二阶段由人区分当次信息与稳定要求。`server-17`、连接池上限由 200 调为 60、时间与服务名均为构造值，只属于旧材料。候选根规则保留三项要求：区分事实、推断和待验证项；先后不能直接写成因果；根因注明对应记录位置。此时 Python 只为读者展示候选文件，尚未把它写入实验项目，不会提前影响第一阶段的新任务。

第三阶段直接在 notebook 写入根目录 `AGENTS.md` 与 `payment-service/AGENTS.md`，使用完全相同的新事故任务，仅改变工作目录（cwd）。实验项目的 `.git` 根标记限定查找范围：从根目录启动不向下扫描服务目录，从服务目录启动则从根到当前目录组合两级内容。再写入服务目录的 `AGENTS.override.md`，独立启动新会话，核对根规则仍在、优先文件进入输入、同层原规则没有合并。优先文件替换的是这一层整份规则，需要保留的本地内容须写完整。临时文件在 `finally` 中撤下。

三组 `act-result` 过程表格均左对齐；第三组分别对照工作目录、同场事故回答与同层选择。请求装配记录保存每次实际输入及各条规则的位置，完整原始请求另存为 `request-*.json`。只核对请求的 `input` 字段，不用模型回答、工具定义或基础指令冒充项目规则已加载。

源 notebook 共十二格、七个代码格，准备格七行，分享时保留无执行输出的源文件。`examples/notebook04_setup.py` 负责依赖与隐藏输入；`examples/notebook04_story.py` 负责材料、展示、留痕和收尾。会话创建、SDK执行、规则文件写入与撤下直接在 notebook 展开；等待进度、超时中断和结果保存另由辅助代码处理。最后一组表格展示后自动关闭连接；中途代码格报错也会撤下临时文件并释放连接，重新运行准备格会先关闭旧连接。

`examples/notebook_support.py` 准备 SDK 连接：真实 `codex app-server` 在独立子进程运行，SDK通过stdio通信，再经本地适配器调用 GLM-5.2。Notebook显式传入 `Sandbox.full_access`（工具可以访问本次运行环境）与 `ApprovalMode.deny_all`（不申请额外批准），外层权限仍然生效。结合请求中装入的规则与报告的实际措辞，核对项目要求怎样影响新任务的调查和判断。

自动化核验使用装有 notebook 执行依赖的 Python 3.12：

```bash
python examples/04-agents-md/run_validation.py --mode offline
python examples/04-agents-md/run_validation.py --mode live
```

离线核验设置 `LAB_VALIDATION_RUN_ID`，只准备、展示和比较构造材料，不调用模型、不启动适配器、不模拟模型回答或请求。在线核验从环境变量 `GLM_API_KEY` 取凭据，再经过 notebook 隐藏输入分支执行整本。两种模式分别保存到 `validation/runs/nb04-v1-<模式>-<时间>-<随机后缀>/`，包含执行后的 notebook、`reading.html`、结果与每格耗时；`offline-latest.json`、`live-latest.json` 分别指向最近记录。原始材料、请求、任务轮记录与连接关闭记录保存在各次 `.runtime/` 目录中，原始运行记录留在本机。
