# Lab 03｜文件在磁盘上，模型就已经知道了吗？

[打开 notebook](workshop.ipynb)，用 Python 3.12 内核从头运行。未设置 `GLM_API_KEY` 时，准备格会弹出隐藏输入框；全程只需输入这一个密钥。缺失的 `openai-codex==0.154.0`、`litellm[proxy]==1.101.0` 和 `httpx[socks]` 会自动补装。

这是专栏《自进化 Agent 实战》03 讲《上下文引擎：模型每轮对话都会看见什么？》的配套练习。练习使用构造的故障调查材料，目标是掌握处理真实场景的能力。

| 十二格导览 | 动手做什么 | 跑完看什么 |
| --- | --- | --- |
| cell0—2｜题面、参考答案与准备 | 阅读系统设计题，一键准备材料与连接 | 工作目录、任务历史与当前请求的区别 |
| cell3—5｜文件就在目录里，Agent 为什么没有用上？ | 同一会话先只依据告警回答，再读取部署文件后回答同一个问题 | “同一问题”和“本次实际回答”两列 |
| cell6—8｜模型这一轮看见的，不是整个工作目录 | 打开请求，配对命令和回执，找随机编号首次进入的请求 | 基础指令、工具定义、任务消息、开发者规则及工具结果的实际位置 |
| cell9—11｜谁来准备模型每一轮看到的内容？ | 在同一会话追问采集编号与时间，比较输入文件 | 原工具结果是否保留、本轮有无新工具调用、文件是否改变 |

第一阶段把 `materials/deployment.md` 写到本次工作目录，替换其中的随机采集编号；部署文件记录 01:40 将连接池上限由 200 下调到 60，采集时间为 02:07。告警、服务名、时间、数值与编号均为构造值。编号只写在文件里，不写入任务或开发者规则。Python 为读者展示文件，不会把文件正文自动交给模型。代码直接用 `codex.thread_start(cwd=..., developer_instructions=rule, ...)` 开会话，再分别调用 `thread.turn()` 和 `turn.run()` 完成回答；第一次明确不读文件或调用工具，第二次才要求读取 `deployment.md`。两次回答原文保存，不把时间相邻解释为已经确认因果。

第二阶段沿用 `command_receipts` 按调用编号配对真实命令与回执，用 `tool_output_contains` 只检查工具结果中的编号。请求表逐项展示 `instructions`（基础指令）、`tools`（工具定义）和 `input`（消息及工具记录）；开发者规则在开发者消息中另行核对。表内给出规则、任务和编号附近的真实片段，完整请求保存在本次运行目录。这些记录来自客户端发给本地适配器的 Responses 请求体，能直接对照本轮任务实际携带了哪些内容。

第三阶段不重述文件内容，只追问采集编号与采集时间。检查追问首次请求是否保留原回执的调用编号与完整返回，核对新增工具调用及客户端命令事件，并比较工作目录全部输入文件的 SHA-256。文件在目录里不等于已经进入上下文，客户端事件记录也不等于这一轮的完整输入。

源 notebook 共十二格，其中七个代码格；准备格七行。模型调用、请求切片、回执配对与输入比较直接在 notebook 执行；`examples/notebook03_setup.py` 负责依赖与隐藏密钥输入，`examples/notebook03_story.py` 负责材料、表格、留痕与收尾。`lab.watch()` 提供等待保护，`lab.record_result()` 保存已经返回的SDK结果。最后的过程表格展示后自动关闭连接。中途代码格报错也会关闭本次连接；从准备格重新运行时先关闭旧连接，再创建新目录。

模型连接由 `examples/notebook_support.py` 准备，使用 GLM-5.2。Notebook显式传入 `Sandbox.full_access`（工具可访问本次运行环境）与 `ApprovalMode.deny_all`（不申请额外批准），外层权限仍然生效。文件前后不变只证明本次执行没有改输入，不把文字要求当作操作系统隔离。

自动化核验使用装有 notebook 执行依赖的 Python 3.12：

```bash
python examples/03-context-engine/run_validation.py --mode offline
python examples/03-context-engine/run_validation.py --mode live
```

离线核验设置 `LAB_VALIDATION_RUN_ID`，仅准备、展示和比较构造材料；不调用模型，不启动适配器，不伪造模型回答、请求或工具回执。在线核验从 `GLM_API_KEY` 环境变量取得凭据，再经过 notebook 的隐藏输入分支执行整本，记录输入次数、每格耗时、模型请求数与任务轮数。

两种模式分别保存到 `validation/runs/nb03-v1-<模式>-<时间>-<随机后缀>/`，包含执行后的 notebook、`reading.html` 与结果；`offline-latest.json`、`live-latest.json` 指向各自最近一次记录。材料、请求、工具事件、输入文件哈希与连接关闭记录保存在各次独立的 `.runtime/` 目录中。分享时使用无输出的源 notebook，运行记录留在本机。
