# Lab 08｜按需调阅关键上下文：一项 Skill 的内容怎样逐层出现？

[打开 Notebook](workshop.ipynb)。这是专栏《自进化 Agent 实战》08 讲《渐进披露：按需调阅关键上下文》的配套练习。事故材料中的日期、实例名、域名、请求编号和数值均为构造值。

默认从 Notebook 在线运行；也提供不启动模型的离线检查。执行结果、带输出的阅读页与原始检查材料保存在本地，不随练习发布。

```text
08 讲练习
├─ 阶段一：Context 预算与分层
│  └─ 同一套文件全部装入 / 只装主干，比较字符占用
├─ 阶段二：Agent Loop 推动按需取用
│  └─ 无关任务 / 匹配任务分别观察，自然选用 → 正文 → 附件 → 脚本结果
└─ 阶段三：Harness 接入与描述边界
   └─ 按实际请求和同编号回执核对是否误选、漏选以及读取顺序
```

第一阶段由代码格直接读取四个文件，拼接“全部写进入口”的对照文本，用字符数直观比较主干和附件的篇幅。随后查看实际请求，追踪这些内容在调查的哪一步进入模型输入。Notebook 为读者展示的文件与模型通过工具取得的文件分开记录。

第二阶段直接调用 `codex.thread_start()` 创建两个独立会话，Codex 从 `.agents/skills/legacy-payment-oncall/` 发现能力索引。第一个只收到旅行照片标题任务，第二个收到历史支付模块的调查任务。两次都只传 `TextInput`，不点名 Skill、不附正文路径，不用 `SkillInput` 强选，也不提示无关任务“不要选 Skill”。由模型结合任务和描述自行判断是否读取方法，再按调查进度取用附件、写报告、执行检查。每次直接调用 `turn.run()`；两类任务的请求范围和 Thread 编号分别保存。

第三阶段分别展示无关任务、匹配任务的索引可见情况、正文成功读取回执、附件首次返回位置及完整命令回执。通过 `call_id` 配对请求和结果，不把用户提示词或助手自述当成读取。未触发、误触发、读取失败都按本轮轨迹显示，不用本地词语匹配替代模型行为。

最后核对输入与方法未变并关闭本次连接。正文是否被取用、参考资料是否按顺序返回、报告引用是否成立是不同问题；一次正确选择也不能证明描述对所有任务都合适。显式 `SkillInput` 可以另做加载机制对照，但不能替代这里的自然选择观察。

## 离线运行

在仓库根目录使用已有 Python 执行，离线检查只使用标准库：

```bash
python examples/08-progressive-disclosure/run_validation.py --mode offline
```

离线入口不执行 Notebook、不安装依赖、不读取密钥、不启动 SDK 或模型。它检查源码，并以明确构造的回执测试观察逻辑：用户文字不能冒充正文读取、错配编号不能算成功、无关任务读取 Skill 会暴露误触发。临时文件仅在本讲 `.runtime/` 中创建并清理；不会生成“模型已自然选中”的结果，也不会将旧材料回放重新标为成功。

真实调用验证使用 `--mode live`，需要 Python 3.12、已安装的 Notebook 及样板依赖和 `GLM_API_KEY`。它执行两次真实任务，检查独立 Thread、无关任务未读正文、匹配任务成功读取正文、参考和模板按进度回流、脚本结果返回而源码未常驻，以及进程与端口释放。新运行以 `nb08-v2-` 命名，生成本地阅读页；离线检查不能代替这些行为验证。

完整重跑准备格会先关闭上一轮连接。代码格中途报错也会触发关闭；自动验证始终在结束处理里再关闭一次。沿用样板的 `Sandbox.full_access` 与 `ApprovalMode.deny_all`，实验目录表示任务范围，不能把它当成操作系统隔离。
