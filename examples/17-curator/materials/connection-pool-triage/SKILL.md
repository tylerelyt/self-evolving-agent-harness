# 连接池诊断

所有数据均为构造教学数据。只读诊断，不执行扩容、切换或重启。

1. 确认目标集群、服务和告警时间窗口，不能混入其他环境的同名服务。
2. 对照 active、idle、max、waiting、请求量与连接持有时间。请求量持续增长且连接正常归还时，考虑容量或慢查询；不能只凭 active=max 判定泄漏。
3. 当请求量恢复而 active 仍不下降，或存在长时间未归还的连接时，检查连接释放路径。
4. 一般连接池指标解释见 [指标说明](references/pool-metrics.md)。涉及连接泄漏时查找对应诊断方法。
5. 报告观察、判断和下一步验证；数据不足时明确待确认。

任务提供 `diagnostic_query` 时，先获取 metrics 和 holders；怀疑泄漏时再查 release_paths 的覆盖。按实际数据判断需求是否超过容量、负载回落后连接是否归还。释放代码未覆盖时，不把疑似泄漏说成已确认。读取相关支持资料中的完整诊断规则，按任务的 JSON 接口提交判断、实际证据编号及可验证下一步；不能只返回分类标签。
