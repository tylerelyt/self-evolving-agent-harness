# 综合实践｜跑完一次学习循环，再决定下一次采用什么

一笔订单有两笔成功款项，分别是 450 元和 450 元。基线写对了总额，评分器却只取了第一个 450。候选在缺少渠道受理字段时给出了内部队列，评分器又没有查这个前置条件。用这轮支付查询练习，亲手核对一次候选为何应暂缓采用。

这里用构造的订单快照、预置答复和教学复盘规则，离线重做正文中的证据核对与采用决定。答复、查询回执和分数都是这套夹具的产物。要操作真实 Hermes、巡检服务和原生 SkillClaw，请运行[第 23 讲总装练习](../capstone/README.md)。

## 先跑两次独立回放

在仓库根目录运行。只需要 Python 3.9+ 标准库，模型调用费用为零。

```bash
python3 workshop/practice/replay.py
python3 workshop/practice/replay.py --judge calibrated
```

每次运行生成独立的 `workshop/practice/runtime/<编号>/`。第一条使用故意保留三个缺陷的评分器，主组各为 1/4，采用门槛因校准失败和没有增益而挡住候选。第二条使用修正后、仅支持本练习固定答复格式的评分器复核同一组预置答案。它识别出两笔款项的合计、最终状态及队列前置条件。主组各为 2/4，新问法还暴露了一次退步，正式版仍选基线。这些得分属于本练习的构造数据。

## 按记录核对闭环

| 记录 | 核查问题 |
| --- | --- |
| `inputs.json`、`protocol.json` | 两组运行使用的订单、问题、预置答复、标注和采用门槛如何固定？ |
| `calibration.json` | 评分器能否同等接受 `900` 和 `450 + 450 = 900`，同时拒绝把渠道受理当到账、缺少前置条件仍选队列的答复？ |
| `experience/`、`review.json`、`methods/` | 后台从哪个落盘记录读到了什么？候选的指纹和那份记录如何对应？队列名来自教学规则，经历只提供触发这条规则的事实。 |
| `pairs.json`、`pairs/` | 同一道题的两个记录是否引用相同问题和订单快照、使用独立回放编号，只换 Skill？哪一处原答和判分不一致？新问法复用了同一个订单，用于检查措辞变化。 |
| `decision.json`、`official.json` | 哪些门槛没有通过？正式版具体指向哪个内容指纹？ |
| `sharing/`、`recovery-rehearsal/check.json` | 正式组与候选复测组分别读取哪个副本？同一订单的答复差异能证明什么？独立副本恢复之后，新回放读取了哪个版本？ |

`status.json` 在整轮结束时生成。遇到中断，保留已有记录并另起一轮。回放通过文件复制练习分发和快照恢复，候选复测目录与正式指针分离。

## 交付一份采用记录

1. 从两次运行中各选一个反例，对照同一原答、独立标注和评分结果。说明这是读错表达还是漏了业务要求。
2. 在 [fixtures.json](fixtures.json) 增加一组校准正反例。保持业务含义相同、只改表达时，判分应一致。改掉关键前置条件时，判分应改变。保留旧运行的原答，用新目录重跑。
3. 用几句话写明经历回流、复盘读取、候选生成、成对比较和最后采用决定的证据路径。若换成自己的重复任务，另备一组在候选选择后才打开的留出题，用来检验新任务的表现。
