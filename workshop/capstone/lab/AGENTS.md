# On-call 工作台练习

你在帮助读者逐关实现自己的 On-call Agent。当前任务由读者这一次指定的 stage 决定。每次完成这一关、运行检查，再让读者回到工作台观察实际行为。

## 修改范围

- 实现文件是本目录的 `self_improvement_agent.py`。只补当前 stage 对应的函数，保留已通过关卡和其他 TODO。
- 可以读取本目录的 `README.md`、起始代码，以及上层提供的运行时和工具接口。
- 不读取或导入 `solutions/`，不从上层完整参考实现复制函数答案。根据当前函数约定和提供的运行时接口实现。
- 不修改检查器、评分规则、故障环境、工作台、运行时或其他课程文件，不删除或伪造运行证据。
- 不修改读者的模型配置、个人 Hermes Home 或已运行的实验目录。

## 每次请求的工作顺序

1. 读本目录 `README.md`，确认读者本次指定的 stage、对应函数、检查命令和工作台观察位置。
2. 阅读该函数的参数和返回值约定，以及本关允许使用的运行时接口。
3. 只实现当前关的函数，然后从仓库根目录运行下面的检查，将 `N` 替换为本次 stage。

   ```bash
   .deps/hermes-agent/.venv/bin/python -B workshop/capstone/lab/check.py --stage N \
     --workbench workshop/capstone/runtime/workbench
   ```

4. `--workbench` 使用读者当前工作台的状态目录；默认目录见上面的命令，其他目录以面板和读者本次请求为准。根据失败输出回查实际工具结果或 Session 证据，修正当前实现并重新运行。检查通过后，再核对本次 diff 是否仅包含当前关的必要修改。
5. 用三个短点结束本关，写明修改了哪些函数、检查结果与证据位置、回工作台的下一步操作及观察位置。等待读者请求下一关。

## 检查和观察

- 使用读者自己的实现运行检查，检查命令不加 `--solution`。
- 通过检查后，不自动继续实现后续关卡，也不自动替读者点击工作台中的故障、恢复或阶段操作。
- 遇到依赖或服务连接错误时，先核对本项目提供的安装和状态入口。实现仍未通过时，如实记录失败输出及已完成的改动。
- 分开报告代码检查、工作台加载和现场行为。只有面板实际显示或运行证据能够证明的结果，才写为已观察到。
