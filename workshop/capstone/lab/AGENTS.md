# 帮读者接入 On-call Agent

这里逐步搭建本讲的双实例 On-call 自进化系统。先阅读上层 README 的「运行双实例演练」：A 的支付与 B 的订单在两套本地 HTTP 环境中持续巡检，受控两轮默认使用脚本模型，第二轮交换故障类型，验证改进后的 Skill 是否实际采用。

原始初判 Session 进入 SkillClaw，补查分支用于事故处置与复盘；候选经过独立冻结三用例的新旧成对评测，再正式发布，并在新现场验证采用或回退。`self_improvement_agent.py` 的受控两轮入口是完整验收入口。业务工作台和持续 SRE 对话提供附加的操作、观察与复核，共用原有 Skill、巡检和演化主链。

按读者的自然需求识别当前阶段，每次完成一步、自动检查，再请他回业务页面观察。四步的实现目标始终是上述系统。

## 识别本次需求

不要求读者使用固定口令。按意图匹配：

| 读者会怎样说 | 本次 stage | 当前文件中的实现入口 |
| --- | --- | --- |
| 让 Agent 上线、开始巡检、持续抽查服务 | 1 | `patrol_config` |
| 接手告警、调查故障、通知我、交接后继续巡检 | 2 | `route_alert`、`branch_report`、`notify_operator` |
| 记住事故、让新任务查历史、给它 Memory | 3 | `recall_memory` |
| 从事故改进 Skill、评测后发布、验证下一次采用 | 4 | `release_policy` |
| 下一步、继续 | 最早仍未实现的阶段 | 先核对代码和检查记录 |

按顺序推进。如果前面的必要能力仍是 stub，先完成最早缺失的一步并说明原因。**一次只实现一个阶段，检查通过后停止。** 读者明确要求一次完成多步时，按他指定的范围执行。

## 修改范围

- 只修改本目录的 `self_improvement_agent.py`，实现本次阶段的函数，保留已完成能力和后续 TODO。
- 可以读取本目录 `README.md`、起始代码、上层提供的运行时和工具接口。
- 不读取或导入 `solutions/`，不从上层完整参考实现复制答案。按函数约定和提供的运行时接口实现。
- 不修改检查器、评分规则、故障环境、工作台、运行时或其他课程文件，不删除或伪造证据。
- 不修改读者的模型配置、个人 Hermes Home 或已经运行的实验目录。

## 实现后自动检查

读者不用专门要求你检查。完成当前阶段后，从仓库根目录运行，将 `N` 替换为本次 stage：

```bash
.deps/hermes-agent/.venv/bin/python -B workshop/capstone/lab/check.py --stage N \
  --workbench workshop/capstone/runtime/workbench --live
```

工作台默认连接真实模型。读者从「练习与运行」复制的本步需求会携带当前模式，按该模式检查。若工作台明确使用 `app.py --offline`，检查命令去掉 `--live`，并说明本次验证的是离线接线。上面命令中的路径是示例，`--workbench` 必须替换为读者当前工作台终端打印的实际 `Workbench state`，也可从「练习与运行」和本次请求核对；`--new-state` 会为每次启动分配独立后缀。不要擅自更换模式或另开一个目录来掩盖失败。

根据失败信息回查工具结果和会话记录，修正当前实现，重跑到通过。第 3、4 阶段包含真实恢复窗口，保持检查运行直到完成。遇到模型或依赖错误时，核对本项目的安装与连接入口，如实记录尚未通过的原因。

检查通过后核对 diff，仅包含本次允许的实现。用三个短点结束：改好了什么业务能力、检查结果与证据、回工作台该做什么。提示读者在「练习与运行」启动或应用代码，再回「概览」「指标」「日志」「变更」及 SRE 对话观察。需要后续能力时，给出下一步的自然需求，等待读者提出。

## 业务页面是观察入口

- 不把函数名、命令、源码哈希或内部文件结构当作读者的主要操作流程；这些信息留在实现说明、检查记录或「执行证据」。
- 引导读者在同一段 SRE 对话里提任务和追问，跨业务页继续查看；验证跨会话 Memory 时，再点击「新建对话」。
- 实现完成后，不自动替读者注入故障、申请或批准恢复、复盘事故或继续实现下一阶段。工作台的恢复由读者核对绑定范围后明确批准，继续等待巡检的两段健康窗口。
- 分别报告检查通过、当前代码已应用和现场行为已观察。只有实际运行证据能证明的结果，才写为已观察到。
- 最终目标是经历、Memory、Skill 候选、独立评测、发布和下一轮采用构成闭环。阶段检查、持续对话或并行复核完成后，完整验收仍以受控两轮的记录为准。
