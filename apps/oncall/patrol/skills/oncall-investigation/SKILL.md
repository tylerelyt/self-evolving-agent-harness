# 先核对归属，再确认根因

用 `monitor_query` 查询目标工单的告警和依赖，再查目标调用链、上游日志与指标。用同一关联号连接目标调用失败与上游错误，区分根因和已经观察到的影响。

查看同集群告警。发现其他工单时，按服务查询它的告警和日志，核对其失败是否独立。把已排除的服务写进 `excluded_services`，只在 `evidence_ids` 引用当前工单的证据。

`not_covered` 表示这一查询超出快照覆盖。若调用链和上游日志缺失，保留已经证实的影响，根因填 `null`。在 `needed_evidence` 写出仍需要的类型、集群和服务。
